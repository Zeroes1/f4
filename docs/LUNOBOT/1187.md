# f4 #1187

## Parts 1–3 of 3

When `Panel/ArchiveTarIndexCache` is disabled, opening a tar archive still
needs a SQLite index because the current tar reader requires an index path.
This part keeps that index only for the lifetime of the opened filesystem and
removes it, including SQLite side files, when the filesystem closes. The
failure path removes a partially created index as well.

A regression test opens and reads a tar archive with the cache disabled and
checks that no index remains in the user cache afterward. The two remaining
reported cache-cleanup cases are external rename/removal and stale renamed
indexes; the former is handled in part 2 and the latter is left for part 3.

Part 2 removes an index for the same content under an old path when a tar
archive was renamed outside f4. The content fingerprint is shared by both
paths, so the old index is no longer retained after the renamed archive is
opened. A regression test covers the external rename.

Part 3 records the archive path belonging to each f4 cache prefix. When a tar
archive is opened, records whose archive no longer exists are removed together
with their indexes. The record moves with f4's own rename operation and is
removed by the rebuild-all action. A regression test covers an archive deleted
outside f4; the cache is cleaned when the next tar archive is opened.

Verification is performed by GitHub Actions according to the Lunobot workflow;
local builds and tests are intentionally not run.
