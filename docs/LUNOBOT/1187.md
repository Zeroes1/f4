# f4 #1187

## Part 1 of 3

When `Panel/ArchiveTarIndexCache` is disabled, opening a tar archive still
needs a SQLite index because the current tar reader requires an index path.
This part keeps that index only for the lifetime of the opened filesystem and
removes it, including SQLite side files, when the filesystem closes. The
failure path removes a partially created index as well.

A regression test opens and reads a tar archive with the cache disabled and
checks that no index remains in the user cache afterward. The two remaining
reported cache-cleanup cases (external rename/removal and stale renamed
indexes) are left for later parts.

Verification is performed by GitHub Actions according to the Lunobot workflow;
local builds and tests are intentionally not run.
